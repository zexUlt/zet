# Правила для документов

## Два языка

- `docs/en/` — каноническая версия, `docs/ru/` — полный перевод.
- **Нумерация разделов и заголовки таблиц совпадают** — расхождение должно ловиться структурным `diff`-ом.
- Правка одной версии без второй не коммитится. Забыл перевести — документ рассинхронизирован, а не «допишем потом».
- В русской версии идентификаторы, имена сообщений, поля wire-формата и названия ADR остаются английскими.

## Достоверность

Каждое утверждение о чужом коде помечается. Маркеры одинаковые в обеих языковых версиях — так они не разъезжаются при переводе:

- `[V]` verified — прочитано в исходниках, ссылка `файл:строка` обязательна, коммит указан в шапке документа.
- `[I]` inferred — вывод из кода; цепочка рассуждений приводится целиком, иначе это не вывод, а догадка.
- `[U]` unverified — предположение. Такие живут в отдельном приложении, а не вперемешку с фактами.

Правило: `[V]` не может быть выводом, `[I]` не может стоять без цепочки. Если проверить не удалось — ставь `[U]`, а не повышай уверенность.

## Ссылки

- Формат `путь/файл.cpp:123`, путь относительно корня изучаемого проекта.
- Коммит фиксируется один раз в шапке документа. Ссылки на строки GitHub запрещены — они разъезжаются с кодом (у EternalTerminal собственный `docs/protocol.md` ссылается на давно устаревший коммит).
- Ссылка без строки допустима только для файла целиком, когда речь о нём как о единице.

## Тон

- Разбор чужого проекта — это разбор решений и их последствий, а не памфлет. Раздел «что сделано правильно» обязателен и пишется всерьёз.
- Уязвимости описываются как архитектурные следствия. Ничего не эксплуатируется, PoC не пишется.
- Числа вместо оценок: не «большой буфер», а «64 МБ»; не «быстро», а «за один RTT».

## Структура

- Таблица лучше абзаца везде, где сравниваются варианты.
- У каждого архитектурного решения — явный trade-off: что теряем, а не только что получаем.
- Отвергнутые альтернативы записываются с причиной отказа. Решение без альтернатив выглядит как отсутствие выбора.

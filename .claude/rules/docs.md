# Правила для документов

В `docs/` живут ровно два файла, и оба обязаны окупать своё существование:

- `prior-art.md` — что уже сделано другими, со ссылками на исходники. Справочник при написании кода.
- `design.md` — наши решения с обоснованием и trade-off'ами. Источник истины; расхождение кода с ним правится осознанно в одну из двух сторон.

Третьего документа быть не должно. Если тянет завести — сначала ответь, к какому коду его будут открывать.

## Ссылки на чужой код

- Формат `путь/файл.cpp:123` относительно корня изучаемого проекта. Диапазон — `:105-151`.
- Коммит каждого чекаута зафиксирован в таблице версий в шапке `prior-art.md`. Добавляешь новый проект — добавь строку туда же.
- Ссылки на строки GitHub запрещены: они разъезжаются с кодом. У самого EternalTerminal `docs/protocol.md` ссылается на давно устаревший коммит.
- После правки ссылок прогнать `ZET_REF_ROOT=<каталог с чекаутами> tools/check_refs.py`.

## Достоверность

- Утверждение о чужом коде без ссылки — не утверждение. Либо ставь `файл:строка`, либо пиши «не проверено» словами.
- Проверить не удалось — так и напиши. Повышать уверенность задним числом нельзя.
- Вывод из кода отделяй от прочитанного в коде: приводи цепочку рассуждений, иначе это догадка.

## Тон и содержание

- Разбор чужого проекта — это разбор решений и их последствий, а не памфлет. Раздел «что сделано правильно» обязателен и пишется всерьёз.
- Уязвимости описываются как архитектурные следствия. Ничего не эксплуатируется, PoC не пишется.
- Числа вместо оценок: не «большой буфер», а «64 МБ»; не «быстро», а «за один RTT».
- У каждого нашего решения — явный trade-off: что теряем, а не только что получаем.
- Отвергнутые альтернативы записываются с причиной отказа. Решение без альтернатив выглядит как отсутствие выбора.
- Таблица лучше абзаца везде, где сравниваются варианты.

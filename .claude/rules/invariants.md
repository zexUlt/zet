# Инварианты zet

Жёсткие правила. Каждое поддержано гейтом в CI — нарушение роняет сборку, а не обсуждается в ревью. Если правило кажется мешающим, это повод обсудить правило, а не обойти его.

## 1. Никакого аварийного завершения по данным из сети

В `zet_wire`, `zet_session`, `zet_crypto` не должно быть `abort`, `exit`, `_exit`, `assert`, `__assert_fail`, `std::terminate`. Проверяется `nm` по объектным файлам.

У EternalTerminal 164 fatal-точки, и часть достижима из сети: неудачная расшифровка, неизвестный тип пакета, битый protobuf. Каждая означает падение процесса, обслуживающего **все** сессии. Одна из них стала pre-auth уязвимостью.

Единственная `zet::fatal()` живёт в `*_main.cpp` и вызывается только до начала обслуживания.

Логгер не имеет уровня FATAL. Библиотека, у которой такой уровень есть, — приглашение к катастрофе.

## 2. Ни одной мутации состояния сессии до аутентификации

До проверки MAC в resume-хендшейке не меняется ничего: не отвязывается старый сокет, не сбрасываются буферы, не двигаются счётчики.

Обеспечивается типом, не дисциплиной: до аутентификации доступен `SessionRef` без мутирующих методов; `SessionHandle` можно получить только из `authenticate(...) -> std::expected<SessionHandle, AuthError>`.

Образец — WireGuard: единственный сеттер endpoint (`peer.go:279`) вызывается только после провала-гейтов AEAD и anti-replay (`receive.go:450,454,457`). Открытый индекс используется исключительно для выбора ключа.

Следствие: идентификатор сессии `sid` — маршрутный ярлык, а **не** credential. Его утечка не даёт ничего. У EternalTerminal `clientId` был единственным credential при реконнекте, и починить это не удалось.

## 3. Никаких `sleep` в горячем пути

`sleep`, `usleep`, `nanosleep`, `std::this_thread::sleep_for` вне тестов запрещены — проверяется grep-гейтом.

Ожидание — только через таймерную очередь общего event loop. Таймаут `epoll_wait` вычисляется из ближайшего дедлайна; фиксированных тиков нет.

У EternalTerminal 25 таких мест, включая `sleep(1)` внутри цикла обслуживания сессии и реконнект без экспоненциального backoff.

## 4. Ноль внешней телеметрии

Ни crash-reporting, ни метрик, ни проверки обновлений, ни «анонимной статистики». Ни в каком режиме сборки, ни за каким флагом — кода отправки не существует.

Гейт: `nm`/`objdump` по готовым бинарям не находит исходящих сетевых примитивов (`getaddrinfo`, `connect`, `curl_*`, TLS-символы) вне транспортного модуля. Плюс интеграционный тест: за полную сессию агент не делает ни одного `connect` никуда, кроме своего пира.

Вся диагностика остаётся там, где развёрнут бинарь: логи в stderr/journald, счётчики через `zet-agent --stats` по локальному unix-сокету, дампы кадров через `zet-dump`.

## 5. Секреты нелогируемы по типу

Ключи и passkey живут в `Secret<T>` — без оператора вывода, без неявного преобразования. Залогировать ключ должно быть невозможно, а не «не принято».

## 6. Бюджеты размера бинарей

`zet` ≤ 1.2 МБ, `zet-agent` ≤ 1.5 МБ (до M6), `zet-muxd` ≤ 600 КБ. Статическая линковка, `strip`, release-пресет. Гейт падает при превышении.

Не влезли — не раздувай бюджет молча и не выкидывай фичу молча. Выноси расхождение с цифрами: сколько байт стоит, что даёт.

## 7. Каждый лимит — именованная константа

Ни одного магического числа в коде: размеры кадров, таймауты, ёмкости очередей, число попыток. У каждого — имя, комментарий с обоснованием и место в документации протокола.

## 8. Ровно одна рантайм-зависимость

libsodium, спрятанная за интерфейсом `zet::crypto` из шести функций. Всё остальное — своё. `external/` пуст.

Новая зависимость добавляется только после обсуждения и с ADR. CI проверяет список разрешённых `find_package`/`FetchContent`.

## 9. Sans-I/O ядро

`zet_wire` и `zet_session` не делают ни одного системного вызова. Протокол — чистая функция от входящих байт, событий и времени.

Это не эстетика: отсюда бесплатно берутся фаззинг на миллионах exec/s, детерминированные тесты реконнекта с виртуальными часами и отсутствие гонок в тестах.

## 10. Разбор только через типизированный ридер

В `zet_wire` запрещены прямая индексация, `substr`, `memcpy` по внешним данным и `.at()`/`operator[]` на wire-буферах — проверяется clang-tidy.

Единственный способ разобрать байты — `ByteReader` с приватным `span` и API вида `read_u32be() -> std::expected<uint32_t, ProtoError>`.

Ошибка несёт диспозицию: `Disposition{Ignore, CloseConnection, KillSession}`. Вызывающий не решает, что делать, — передаёт её в `handle(err)`. Всё `[[nodiscard]]`.

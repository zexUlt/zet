# zet

Собственная реализация «вечного терминала» на C++23 — сессия переживает смену сети, сон ноутбука и обрыв связи без потери байта. С нуля, **без wire-совместимости** с EternalTerminal.

## Работа по этапам — главное правило

Проект идёт этапами M0–M7. **После каждого этапа: показать результат, прогнать критерий готовности, показать его вывод — и остановиться.** Следующий этап не начинается без явной отмашки. Это касается и документов, и кода.

| Этап | Что | Grid |
|---|---|---|
| M0 | каркас, CMake, `zet_core`, CI с гейтами | — |
| M1 | `zet_wire` — фрейминг, AEAD, KDF, автоматы. Sans-I/O | — |
| M2 | `zet_session` — потоки со смещениями, ACK, backpressure, rekey. Sans-I/O | — |
| M3 | `zet_io` — epoll/kqueue, pty, spawn, сигналы через fd | — |
| M4 | сквозной сценарий `zet` + `zet-agent`, **рабочий продукт** | — |
| M5 | `zet-muxd` — один порт на машину, `SO_PEERCRED` | — |
| M6 | серверный grid со scrollback, перерисовка при реконнекте | да |
| M7 | predictive echo на эпохах (опция) | да |

До M6 реконнект работает через replay буфера отправленного; grid на M6 заменяет его как основной путь восстановления.

## Документы

Два файла, оба на русском (код и идентификаторы — английские). Переводить будем, если проект станет публичным.

- `docs/prior-art.md` — разбор EternalTerminal, mosh, tmux/dtach/abduco, WireGuard, QUIC: как устроено, где болит, что забираем. Со ссылками `файл:строка` на исходники изучаемых проектов.
- `docs/design.md` — архитектура zet и ADR. Источник истины по решениям; расхождение кода с ним — повод править одно из двух осознанно.

Чекауты изучаемых проектов лежат вне репозитория. Проверка ссылок: `ZET_REF_ROOT=<каталог> tools/check_refs.py`.

## Стек

- C++23, **только clang** (17+). Один компилятор — один набор диагностик, и libFuzzer у GCC аналога не имеет. CMake проверяет это и падает на GCC.
- Сборка только через пресеты: `cmake --preset dev`, `ctest --preset dev`. Пресеты: `dev`, `asan-ubsan`, `tsan`, `fuzz`, `coverage`, `release`.
- Форматирование — `.clang-format` (google, 4 пробела). Нейминг — `.clang-tidy`, `readability-identifier-naming`, требует `clang-tidy-20`.
- Рантайм-зависимость одна: libsodium (нужна с M1).
- Тесты: pytest для сценарных и интеграционных, doctest для мелких C++-юнитов, libFuzzer для фаззеров.

## Нейминг

| Что | Как | Пример |
|---|---|---|
| классы, функции, методы | PascalCase | `ByteReader`, `ReadU16BE` |
| аргументы и переменные | camelCase | `count`, `messageLength` |
| глобальные константы, `static constexpr` члены | ALL_CAPS | `MAX_FRAME` |
| члены класса | PascalCase, приватные и защищённые с `_` | `Pos_`, `Data_`, публичный `Level` |
| перечисления | префикс `E` | `EProtoError`, значения `EProtoError::Truncated` |
| концепты | префикс `C` | `CByteSource` |
| параметры шаблонов | префикс `T` | `TValue`, `TWidth` |
| пространства имён | lower_case | `zet` |
| имена файлов | snake_case | `byte_reader.cpp` |

## Чем zet не является

- Не мультиплексор — tmux/zellij лучше, и zet для них прозрачен.
- Не замена ssh — bootstrap идёт через ssh, аутентификация пользователя делегирована ему.
- Не кроссплатформа в v1 — Linux, затем macOS. Windows не в планах.
- Не порт EternalTerminal — общих строк кода нет, протокол свой.

## Компоненты

- `zet` — клиент.
- `zet-agent` — по одному на сессию, от имени пользователя, владеет pty, grid и **всеми ключами**.
- `zet-muxd` — опциональный, один порт на машину, непривилегированный, релеит шифротекст и ключей не знает.

Инвариант: **крипто терминируется в агенте; ни один другой процесс не видит plaintext сессии.**

## Референсы для сверки

Клоны изучённых проектов живут в скратчпаде сессии, а не в репозитории: `EternalTerminal` (важен коммит `69b3353`), `mosh`, `tmux`, `dtach`, `abduco`, `wireguard-go`. При новой сессии переклонировать при необходимости.
